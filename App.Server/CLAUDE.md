# App.Server

Plane, grid, Design and Content details: see `plane/CLAUDE.md`.

## Endpoint contract (`apiHandler` in `util/core/util-main.ts`)
Every file in `api/` is a standalone Vercel function, mapped by filename to `/api/<filename>`. Each file's default export is `apiHandler(method, handler)` (it returns the `{ fetch(request) }` object Vercel expects):
1. `method` is the single HTTP method the endpoint accepts: `'POST'` for every endpoint except `api/index.ts` (the plain-text page at the server root), which is `'GET'`. A POST body is always an `ApiRequestDto<T>` (`dto/shared/api-request-dto.ts`: `{ data, versionClient?, language?, requestCount? }`; App.Web's `apiFetch` increases `requestCount` by 1 on every call), parsed once by `apiHandler` (bad JSON → 500); handlers read their own request DTO with `requestData<T>(request)` and never call `request.json()`, and the language with `requestLanguage(request)` (falls back to `Accept-Language`). If `versionClient` differs from `VERSION_SERVER`, `apiHandler` adds a Warning alert asking to reload the page. The session cookie and `Origin`/`Referer` (`domainName`, `sectorKey`) deliberately stay outside the body. `apiHandler` answers `OPTIONS` with 204, rejects any other method with 405 (plus an `Allow` header), and merges `corsHeaders(request, method)` into every response — handlers never deal with OPTIONS or CORS themselves. `dbConnect()` is awaited before every POST handler. If `handler` throws, `apiHandler` logs the error, queues its message as an `AlertEnum.Error` alert and returns a 500 with `data: null` (so a plain `throw new Error('...')` reaches the user as an alert).
2. `handler` delegates business logic to a function in `util/` (via a `<name>Api` entry point in `util/api/`).
3. `handler` returns via `jsonResponse(data, status?, headers?)`, which returns a plain `ApiResult` (not a `Response`); `apiHandler` sends it as an `ApiResponseDto<T>` (`{ data, alerts?, redirectUrl?, responseCount? }`). A handler returning a plain `Response` (only `api/index.ts`) is sent as is, without alerts or redirect url.

## `util/` layout
Three subfolders by role (a relative import between them goes through the folder, e.g. `../core/util-main.js`):
- `util/core/` — infrastructure without domain knowledge: `util-main.ts` (version, domain, sector keys, CORS, `jsonResponse`, `apiHandler`, `alertAdd`, `redirectSet`), `util-db.ts` (shared MongoDB `client`, `DB_NAME`, unique index, `dbConnect`, generic `dbLoad`/`dbLoadByIds`/`dbLoadByFilter`/`dbInsert`/`dbUpdate`/`dbDelete(request, type, ..., isProject = true)`; `dbLoadByFilter` always sets `sectorKey` and `type`, so every load goes through it), `util-storage.ts` (blobs), `util-grid.ts`, `util-grid-data.ts` (`gridDataLoad`: the generic editable data grid of one `DbDto` type; `config.save`/`config.delete` replace the default writes; its parts `gridDataDelete`/`gridDataDeleteConfirm`, `gridDataSaveUpdate`/`gridDataSaveInsert` (return documents, not written), `gridDataNew` are exported for hand-built grids), `util-grid-render.ts` (`gridRender`, the render part of `gridDataLoad`; `GridStateDto.isLayoutStack` toggles `gridRenderLayoutStack` vs `gridRenderLayoutTable`), `util-session.ts` (`userSession(request)`), `util-i18n.ts`.
- `util/db/` — data access per `DbDto` entity (user, debug*, property, design, design-master-detail, content-view, project, schema, dynamic). Owner-specific property logic stays with the owner (e.g. design band properties in `util-design.ts`). Properties attach to an owner `{ ownerName, ownerEnum }`; their `name` is built by `propertyDtoName`.
- `util/api/` — the `<name>Api` entry points called by `api/*.ts` (no other logic). `util-grid-plane.ts` holds the plane registry (`PLANE_LOADERS`, `PLANE_GRID_PATCHERS`) behind `api/grid-load.ts` / `api/grid-patch.ts`, kept apart from `util-grid.ts` so the `plane/` files and `util-grid.ts` don't import each other.

## sectorKey forms
`sectorKey(request, isProject)` (not exported) is `Domain/<domainName>/Global/` (no sign-in required) or `Domain/<domainName>/Project/<projectName>/` (asserts a valid session — throws `'User not signed in!'` after `redirectSet(request, '/sign-in')` — and a selected project, else `'User has no project selected!'`). So `isProject: true` is how sign-in is enforced. `sectorKeyDb`/`sectorKeyProjectDb` append `Type/<type>/`; `sectorKeyStorage`/`sectorKeyProjectStorage` append `Storage/`.

## Sessions
All user calls go through `api/user.ts`: a `POST` `UserRequestDto` whose `requestEnum` (`SignUp`, `SignIn`, `SignOut`, `Session`) selects the operation; `None` or unknown → 400. Responses never include `sessionId`. SignIn sets an httpOnly `sessionId` cookie; `userSession(request)` looks up the `SessionDto` with `isSignIn: true`. `signOut` flips `isSignIn` to `false` rather than deleting the document.

## Grid shape
A `GridDto` has no `rows` of its own: rows are split over `GridDto.tables` (`gridTables(toolbarRows, dataRows, barRows)` in `util-grid.ts`): `tables[0]` toolbar, `tables[1]` data rows (header, find, data rows, or a dialog's content; New rows appended here), `tables[2]` the `gridBarRow()`.
